# SkyGuard

**《光遇》「永无 / 无翼」应急工具**

按一个键 → 立刻关掉游戏（和模拟器）+ 断开网卡，保持若干秒后自动恢复。

> 目的：万一被强制传送、被摆姿势，抢在结果上传到服务器之前切断。

当前版本：`1.1.6-RC1`

---

## ⚠️ 使用前必读

这个工具会：**以管理员权限强制结束你指定的进程**、**临时禁用你指定的网卡**（并可能下发一条临时防火墙规则）、**安装键盘钩子**。

它按「原样」提供，作者不对以下情况负责：

- 未保存的游戏进度丢失
- 断网期间其他网络活动中断（语音、网页等）
- 因误设触发键、误配目标程序造成的任何后果
- **任何游戏账号相关的风险** —— 本工具不注入游戏、不读内存、不改游戏文件，但它的行为特征（装键盘钩子、强杀进程、断网）可能被游戏的安全策略关注，请自行评估风险后使用

**公开说明**：本工具的作用是规避游戏服务器对角色状态的判定，公开分发可能违反《光遇》的用户协议。请自行确认你所在地区与服务条款下这样做的后果。

因为要装键盘监听、要以管理员运行、要结束进程、要禁用网卡，火绒 / 360 / Windows Defender 报警或被拦，以及 Windows 弹出「已保护你的电脑」，**都是预期之内的，不代表有病毒**。处理办法见 [README.txt](README.txt)。

## 它做什么

```
触发键按下
   ├─ ① 快速层（毫秒级）: WFP 动态过滤器拦出站；装不上就下发临时防火墙规则
   └─ ② 硬层（永远执行）: 禁用你勾选的那张网卡
        ↓
   保持若干秒 → 自动恢复网络
```

两层设计是为了抢时间：快的先上，慢的兜底。即使快速层装不上，禁用网卡这一步照样执行，兜底效果不会比以前差。

关键特性：

- **两条触发通道 + 系统热键**，并做实时健康检查（`钩子✓ 轮询✓ 热键11+12`），通道出问题会在界面上变红写明原因，而不是让你以为在保护、真出事时才发现按不动
- **焦点解堵**：游戏窗口卡白 / 无响应时自动接管前台，三档策略（只用系统判定 / Pro / Ultra）
- **每一步自证**：断流前后用探针实测，验不了就写「无法验证」，不会假装成功；错误码一律进日志
- **数据与程序分离**：配置和日志在 `%ProgramData%\SkyGuard`，换版本直接替换程序目录即可，设置不丢
- **单实例**：再双击一次不会开出第二个窗口，而是把已开着的那个切到前面
- **不注入游戏、不读内存、不改游戏文件、不上传任何数据、不开机自启、不装服务、不写注册表**

关于「不联网」：断流探针只 ping **你自己的路由器（默认网关）**，不出局域网、不建立任何连接。若在高级选项里手动添加额外探测目标（如 `1.1.1.1:443`），才会产生真正的外网连接 —— 默认不这么做。

## 运行环境

- Windows（主要在 Win10 上验证过，Win7 / Win8 / Win11 未实机验证）
- .NET Framework 4.x（Windows 自带，无需额外安装）
- **必须右键 → 以管理员身份运行**（要关进程、动网卡，需要管理员权限）
- Windows 11 用户：若开着「智能应用控制」，未签名程序会被直接拦下且没有「仍要运行」按钮，需要手动关闭该功能

## 快速开始

1. 右键 `SkyGuardGUI.exe` → **以管理员身份运行**
2. 首次打开会走设置向导：选要关的程序 → 设一个触发键 → 勾网卡（会自动勾好带【推荐，承载流量】的那张）
3. 点【开始保护】，状态变成绿色的「● 正在保护」，窗口放着别关
4. 出事了按你设的那个触发键

主界面按钮：`[开始保护] [立即处置] [恢复网络] [⚙ 设置] [自检] [打开日志]`

> 想先试手：用【测试】—— 只演练关程序这步，完全不碰网卡。

**完整说明请读 [README.txt](README.txt)**（含杀软拦截处理、更新方式、断流原理、设置窗口五个页签、故障排查）。

## 从源码编译

本仓库**只包含源码和文档，不含编译好的 exe**。

双击 [`编译.bat`](编译.bat) 即可编译，用的是 Windows 自带的 C# 编译器（`csc.exe`，.NET Framework 4.x），**不需要 Visual Studio、不需要 .NET SDK、不需要联网**。编译前请先关掉正在运行的 SkyGuardGUI.exe。

产物是当前目录下的单文件 `SkyGuardGUI.exe`。

> 注意：自己编译出来的 exe 和发布包里的 exe 会「大小一样、SHA256 不一样」—— C# 编译器默认不可复现（PE 时间戳和程序集标识每次都变），这是正常的，不是文件被改过。要核对发布包完整性，请以包内的 `发布清单.txt` / `update.json` 为准。
