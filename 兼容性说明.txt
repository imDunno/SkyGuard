SkyGuard 兼容性说明
================================================================

一、设计上怎么保证"换台电脑也能用"
  1. 不写死本机特征
     网卡名、进程名、路径全部是运行期探测或由你配置; 代码里没有任何"某台机器"的 IP、网卡名或用户名。
     程序只依赖 .NET Framework 4.x + 系统自带的 netsh / ipconfig, 不需要额外装运行库。
  2. 断网方式可选（设置 → 高级选项 → 断网方式）
       · 快速断流 + 禁用网卡  ← 默认, 最稳
       · 只禁用网卡          ← 老方案, 完全不碰 WFP
       · 只用快速断流        ← 不禁用网卡（适合"禁用网卡后要等很久才恢复"的机器）
     快速断流用 WFP 动态过滤器: 毫秒级拦出站, 进程一退就自动消失、零残留。
     装不上会大声写日志, 并按你选的方式继续（默认那条路仍会禁用网卡兜底）。
  3. 每一步都自证
     断流前后用探针实测（默认只 ICMP ping 本机网关, 不出局域网、不建立任何连接）;
     验不了就写"无法验证", 不会假装成功。
  4. 失败都写清楚
     错误码/HRESULT 一律进日志; 恢复失败会弹窗 + 给人工步骤, 并留"断网标记"让下次启动自动补救。
  5. 数据与程序分离
     配置和日志在 %ProgramData%\SkyGuard; 换新版本直接替换 exe 即可保留设置。

二、实测覆盖到的（可作通用性证据）
  · 缩放与布局: 96 / 120 / 144 / 192 DPI 四档缩放下布局自检全部通过;
    主界面与设置窗的五个页签都装得下、无裁剪、底部按钮都在可视区内。
  · 权限: 管理员与非管理员两种环境都有分支; 非管理员时会如实报"环境不足", 不假装通过。
  · 断流: WFP 的"安装 → 拦截 → 撤销 → 恢复"四步实测通过(装过滤器是毫秒级, 拦得住、撤得掉、恢复得了)。
  · 恢复: 断网后恢复网络的完整流程实测通过(无线重连约 5~15 秒属正常, 日志会写明"还没就绪")。
  · 焦点解堵的决策逻辑: 用合成序列跑了 24 个边界情况全部通过 ——
    判定抖动时不抢 / 前台是别的健康窗口时不抢 / 用户已切走时不抢回 / 恢复后只还一次 /
    一轮最多"再抢"3 次 / 抢不到时按静默期节奏继续重试而不是永久停手 / 还焦点失败会补还 /
    停止保护时正好在静默期内也照样还得回去 / 前台切换有延迟也不重复抢 /
    系统卡死标志周期性误报"已恢复"时不被骗 / 探针降级后仍能把焦点还回去 /
    被接管的窗口被销毁重建时把焦点交给它的窗口 / 幽灵窗口标题自动去掉"未响应"后缀 /
    短时间内第二次卡白仍会接管 / 反复卡白时冷却自动退避(1.5s→3→6…最多 30s, 安静一分钟后归零)。
  · 焦点解堵在实机上跑过三轮, 每一轮都改掉一个真问题:
      第一轮: 3 次事件抢了 2 次、还 0 次 —— 窗口被销毁重建时抢了焦点不还;
      第二轮: 查到了具体身份 —— 被抢的是类名 Ghost、标题"光·遇 (未响应)"的幽灵窗口, 而它的
        pid 属于 dwm.exe 而不是游戏, 所以"顺着 pid 找它的新窗口"必然找不到; 现在按
        "同 pid → 标题去后缀 → 配置里的目标程序"三级查找, 并用真实窗口集验证过。
      第三轮: 三级查找在实机上找对了窗口, 但"还焦点"连着两轮被系统前台锁拒; 同时暴露出
        "是否已恢复"的探针带了 SMTO_ABORTIFHUNG, 系统缓存标志没清就一直判"还卡着"、5 秒多
        一次都没重试。现在: 探针去掉那个标志(老实等回音)、前台上报改成异步确认
        (等 250ms 再看, 免得把成功误报成失败)、还焦点多一档"把自己最小化让路"。
        同一次日志也证明"抢焦点"的兜底阶梯有效: 那一轮是用第 4 档(最小化再还原)抢到的。
  · 抢焦点失败(前台锁)时界面会显示"抢焦点失败, 点一下本窗口", 而不是只躺在日志里。
  · 发布前会跑一整套自动化自检(二十多项: 界面响应性、触发通道健康、单实例、快速断流、
    网卡名解析、布局、决策逻辑等), 每一项都核结论、不只看退出码。
    这一版之前刚做过一轮针对"界面无响应"的加固: 在设置窗五页 / 首次向导 / 主窗刷新这些
    必须在界面线程上同步完成的操作里, "连续不处理消息"的时间都被压在 100 毫秒量级
    (Windows 判窗口"无响应"的门槛约 5 秒)。

三、明确没有验证过的（别当成"已支持"）
  · **UAC 安全桌面上收不到按键**（用户态无解，不是本程序的缺陷）
      "是否允许此应用更改你的设备"那个界面、以及任何安全桌面出现时，Windows 不把键盘事件
      发给普通程序 —— 键盘钩子 / RegisterHotKey / GetAsyncKeyState 三条通道一起失效。
      这不是能被代码修好的东西，只能避免把 UAC 窗口一直挂着。
  · **游戏的"真·全屏独占"模式**：焦点解堵把前台切到本程序时，游戏可能切一次显示模式。
      窗口化全屏不受影响。这条只能真机看观感，自检覆盖不到。
  · 没在 Win7 / Win8 / Win11 实机上跑过（只在 Win10 上验证过）
      - Win11 的"智能应用控制"可能拦未签名 exe, 需要手动放行
      - Win7 上没有 Get-NetAdapter 等价能力, 恢复脚本会退到 netsh/PnP 那几级（手动命令仍有效）
  · 没在非中文 Windows 上跑过: 界面与日志是中文, 两个 .bat 内部用 chcp 936
  · 没在多网卡同时在线 / 有线+无线 / 企业域 / VPN / 虚拟网卡混杂的环境下实测
  · WFP 不可用（极少数机器 BFE 服务被禁）时只能靠禁用网卡
  · 焦点解堵在真机上的观感（卡白时不闪、恢复后自动切回）只在实机上人工看过:
    这一版改掉了四处会让画面闪的写法（还焦点时无条件 ShowWindow(SW_RESTORE)、每轮都抢焦点、
    "前台不是自己"就抢回来、拿系统的卡死标志判断"已经恢复"）。其中"是否恢复"改成了直接测量:
    给目标窗口发一个 WM_NULL 并限时 500ms 等回音, 有回音才把焦点还回去; 万一某台机器上这个
    探针不可用（跨会话 / 被安全软件拦）, 程序会自检发现并自动退回用系统标志判断, 不会因此把
    焦点永远扣在本程序身上。但换机器仍要实测 —— 尤其"真全屏独占"模式的游戏, 把前台抢到本
    程序身上可能让它切一次显示模式（默认的窗口化全屏不受影响）
  · 抢前台的兜底阶梯(直接抢 → 绕过前台锁 → 临时置顶 → 最小化再还原)只在真机上才验得了:
    前两档是日常路径(实测能成功); 后两档是"前两档都被拒"时的保命手段, 会让工具窗口动一下,
    已知出现过 1/3 次直接抢失败, 所以才需要它们 —— 到底哪一档能在这台机器上生效,
    只能等真机再遇到"抢不到"时看日志里的"(用兜底方式 N)"
  · 火绒/360 等安全软件: 探针只用 ICMP、不发起 TCP, 实测不再触发"联网控制"弹窗;
    但不能保证所有安全软件都不拦（真被拦了日志里会写清楚）

四、遇到问题先看这里
  · 日志: 设置 → 维护 → [打开日志]（或 %ProgramData%\SkyGuard\SkyGuardGUI.log）
  · 没网了: 双击 恢复网络.bat（右键以管理员运行）
  · 想先验一遍: 程序里点 [自检] → 快速断流自检(推荐, 不经过 .bat, 不会被 Windows 安全警告挡)

五、针对"没实测过的环境"专门写的兜底（代码层面的通用性）
  多网关（有线+无线同时在线 / VPN / 虚拟网卡混杂）
    · 探针会枚举**所有**默认网关, 只要有一个通就算局域网活着 —— 不会因为挑错网关而误判网络状态。
    · 快速断流工作在 WFP 的"出站传输层", 与用哪张网卡无关, 所以 VPN / 虚拟网卡一样被拦住。
    · 断网列表是你在设置里勾的(可多选); 界面给"承载流量"的网卡标了【推荐】, 虚拟网卡标了[疑似虚拟网卡]。
  恢复（换过配置 / 换过网卡 / 中途崩溃）
    · 恢复时除了配置里的网卡, 还会把"断网标记文件里实际禁用过的网卡"一并打开, 避免漏网。
    · 标记文件只在确认恢复成功后才删除; 失败或没提权就保留, 下次启动自动再试。
    · 随时可以双击 恢复网络.bat（它会打开**所有**被禁用的网卡, 比程序更宽）。
    ★ 恢复脚本分两步: 第一轮只打开 SkyGuard **自己禁用过**的那几张
      （名单来自 guard.ini 的 Nic 行 + 断网标记 _netcut_state.txt 的 nic 行），
      免得把用户**故意**禁用的网卡（例如有冲突的第二张网卡、某些 VPN 虚拟网卡）也一起打开；
      万一第一轮没能把默认网关恢复，脚本会自动重试第二轮，那时退化成"打开所有被禁用的网卡"
      这个更宽的老行为 —— 这个脚本"一定能把网要回来"的性质没有降低。
      每一轮都会打印并记录本次打开了哪些网卡（%ProgramData%\SkyGuard\RestoreNetwork.log）。
    ★ 恢复脚本的逻辑在 恢复网络.ps1（纯文本、可逐行审），恢复网络.bat 只负责提权与按轮次调用。
      （拆开的原因: 四级备选阶梯 + 四来源枚举 + ICMP/TCP 双路验证塞进 .bat 的一行会撞 cmd 的
        8191 字符上限, 而且引号转义本身就是脆弱源。缺 .ps1 时 .bat 会退到"只用 netsh + ipconfig"
        的最小应急路径 —— 能救但能力打折, 所以两个文件必须一起分发。）
      打开网卡走四级备选: Enable-NetAdapter → netsh interface set → Enable-PnpDevice →
      Restart-NetAdapter。第三级是专门给"设备管理器里被禁用"的适配器准备的 —— 那种状态下
      netsh 和 Enable-NetAdapter 都打不开它。每一级都打印结果, 不许"看起来在干活、其实没干"。
      验证用 ICMP 与 TCP(53/80) 两条路 —— Win10/11 上路由器不回 ping 很常见,
      只看 ping 会把"其实有网"误判成"没恢复"。
      候选网卡取四个来源的并集(guard.ini / 断网标记 / Get-NetAdapter / netsh+CIM+PnP),
      任何一路读失败都不会让名单变空; "被禁用"的判定只用确凿证据
      (AdminStatus=Disabled 或 ConfigManagerErrorCode=22), 不用 NetEnabled
      —— 实测蓝牙网卡在蓝牙没开时 NetEnabled 也是 False, 但那并不是"被禁用"。
    ★ 新加 /dryrun: 恢复网络.bat /dryrun 只检查不动作, **不需要管理员、不碰任何网卡**,
      会列出适配器、判定哪些处于禁用状态、以及本次会处理哪几张网卡。
      换台电脑（尤其是 Win11）先跑它, 就能在真出事之前确认"这个脚本认得出你的网卡"。
      实测(Win10, 非管理员): 识别出 3 张适配器、正确判定"没有被禁用的网卡"、
      窄模式候选 = WLAN(来自 guard.ini)、并正确判断 WLAN 已启用因而无需处理, 退出码 0。
  · 单实例: 同一时间只允许一个 SkyGuard。
    再启动一个不会开出第二个窗口，而是把已有的窗口切到前面然后自己退出。
    这不是"体验优化"，是修一个真实隐患：两个实例会各装一个全局键盘钩子、
    同时改同一张网卡（先禁后开的顺序一交错就是"断了没生效"或"恢复不了"），
    还会同时写同一份 guard.ini / 日志。而且第二个实例启动时的"清理残留防火墙规则"
    会把第一个实例正在生效的 WFP 拦截拆掉 —— 所以单实例检查放在所有启动动作的**最前面**。
    自检/命令行模式（-version / diagtest / netcuttest 等）不受这个锁约束，
    可以在 SkyGuard 开着的时候照常跑。
  一个网卡都没勾
    · 触发时会明确警告并弹窗: 这次只有快速断流在拦, 没有禁用网卡这层兜底。
  权限 / 策略受限（域环境、非管理员、安全软件拦 WFP）
    · 每一步失败都写错误码; 快速断流装不上就退回你选的断网方式;
      禁用网卡一张都没成功会弹窗提示去"重新探测网卡"。
  安全软件
    · 探针只用 ICMP、不发起 TCP 连接, 实测不再触发火绒"联网控制"; 被拦也如实写日志, 不假装成功。
