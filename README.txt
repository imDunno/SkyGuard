SkyGuard —— 光遇「永无 / 无翼」应急工具
======================================

按一个键 → 立刻关掉游戏（和模拟器）+ 断开网卡，保持若干秒后自动恢复。
目的：万一被强制传送、被摆姿势，抢在结果上传到服务器之前切断。


────────────────────────────────────────────────────────
 怎么用（三步）
────────────────────────────────────────────────────────

  1. 右键 SkyGuardGUI.exe → 以管理员身份运行
     （必须这样，直接双击会被拦下并提示你 —— 它要关进程、动网卡，需要管理员权限）

  2. 第一次打开会走一遍设置向导：选要关的程序 → 设一个触发键 → 勾网卡
     网卡那一步会自动勾好带【推荐，承载流量】的那张，不用改。

  3. 点【开始保护】，状态变成绿色的「● 正在保护」，窗口放着别关。
     出事了按你设的那个触发键。

主界面这几个按钮：

    [开始保护] [立即处置] [恢复网络] [⚙ 设置] [自检] [打开日志]

  · 立即处置!  —— 键盘怎么按都没反应时点它，等于按触发键
  · 恢复网络   —— 只把网卡打开，不关游戏
  · 测试 —— 只演练关程序这步，完全不碰网卡，可以先拿它试手
  · 处置进行中再按触发键 = 忽略（已经在处理了，不会重复处置、也不会打断这一轮）
· 想提前恢复网络：点【恢复网络】，或点【停止保护】——后者会做全套复原
  （撤快速断流 → 打开网卡 → 清断网标记 → 删开机恢复登记）
· 退出程序：一切正常直接退出；保护中弹 1 次确认；网络还断着或有操作没完成时弹 2 次确认
  （设置里的【退出前多次确认】可以关掉）
· 处置结束前 1 秒会再查一次目标是否真的关干净：没关干净就再杀一轮、再断网一轮（最多加一轮）；
  第二轮复查还在，会弹窗告诉你可能是顽固残留进程，由你决定是否恢复网络

  ▸ 同一时间只能开一个 SkyGuard
    再双击一次 exe 不会开出第二个窗口，而是把已经开着的那个切到前面。
    这么做是因为两个一起跑会互相打架：各装一个键盘钩子、同时对同一张网卡发命令
    （先禁后开的顺序一乱，就会出现"断了没生效"或"恢复不了"），还会同时写同一份设置和日志。
    想同时管多个游戏程序？不用开两个 —— 一个 SkyGuard 的【目标程序】页就能勾好几个。

  ▸ 主界面底部那行会显示「通道」状态
    例： 已触发 0 次 · 通道 钩子✓ 轮询✓ 热键11+12
    这是你的触发键"到底能不能按得动"的实时体检：
      · 钩子✓  键盘监听正常（显示"✓(已重装)"表示它曾被你机器上的系统/安全软件悄悄摘掉，程序自己发现并装回来了）
      · 轮询✓  键状态轮询通道正常
      · 热键11+12  系统级热键注册成功了 11 个，另外白送 12 个备用键
    一旦通道出问题，这行会变成红色并写明原因。
    「开始保护」时程序还会做一次就绪检查：三条通道一条都没建立起来，会直接弹窗告诉你，
    而不是让你以为在保护、真出事时才发现按不动。


────────────────────────────────────────────────────────
 杀毒软件报警 / Windows 提示风险 —— 这是正常的
────────────────────────────────────────────────────────

它会装键盘监听、要以管理员运行、结束进程、禁用网卡。
这几件事单独看都很敏感，所以火绒 / 360 / Defender 报警或被拦，
以及 Windows 弹出"已保护你的电脑"，都是预期之内的，不代表有病毒。

  放心的办法有两个：

  1. 源码全在包里（SkyGuardGUI.cs，纯文本，可以用记事本逐行看）

  2. 不放心就自己编译一份 —— 双击 编译.bat 就行。
     用的是 Windows 自带的 C# 编译器，不需要装 Visual Studio、
     不需要 .NET SDK、不需要联网。编译前先把正在跑的 SkyGuardGUI.exe 关掉。

它不注入游戏、不读游戏内存、不改游戏文件、不联网、不上传任何数据、
不开机自启、不装服务、不写注册表。
（"不联网"指不连外网：断流探针只 ping 你自己的路由器，不出局域网；详见文末。）


────────────────────────────────────────────────────────
 被拦了怎么办（三种情况，分别处理）
────────────────────────────────────────────────────────

■ 情况一：Windows 弹「Windows 已保护你的电脑」
  那是 SmartScreen 「没签名的程序第一次运行」的常规提示，不是查杀。
     点【更多信息】→【仍要运行】。
  同一个文件点过一次就不再提示；换新版本会再提示一次（因为换了新文件）。
  小技巧：如果是从网上下载的，先右键文件 → 属性 → 底部勾上「解除锁定」，再运行。

■ 情况二：火绒 / 360 弹「正在记录键盘输入 / 结束进程 / 修改网络设置」
  这是行为告警，不是病毒判定 —— 因为这工具干的正是这三件事。
     点【允许】即可。
  想一劳永逸：把本程序所在的文件夹加进它们的信任区。
     · 火绒：主界面 → 设置 → 信任区 → 添加目录
     · 360： 木马查杀 → 信任区 → 添加目录

■ 情况三：被隔离了（很少见）
  从隔离区还原，再把文件夹加入信任区：
     · Windows Defender：安全中心 → 病毒和威胁防护 → 保护历史记录 → 还原；
       并在「排除项」里添加本程序所在文件夹
     · 火绒：病毒查杀 → 隔离区 → 恢复，然后加入信任区
     · 360： 恢复区 → 恢复，然后加入信任区


────────────────────────────────────────────────────────
 Windows 11 用户注意：智能应用控制（少数机器才会遇到）
────────────────────────────────────────────────────────

只有全新安装 / 重置过的 Windows 11 才会带着这个功能
（从 Win10 升级上来的默认是关闭的，所以多数人根本不会遇到）。
它开着的时候，会把「未知又没签名」的程序直接拦下，而且没有【仍要运行】按钮。

■ 怎么查（3 秒）
   设置 → Windows 安全 → 应用和浏览器控制 → 看有没有「智能应用控制」这一节：
     · 显示「关闭」或「评估」 → 不影响，继续用
     · 显示「启用」           → 会被拦，见下

■ 如果是「启用」
   点进去把它关闭，然后重新运行本工具即可。
     · 较新的 Windows 11：之后还能再打开，随便开关
     · 较老的 Windows 11：关闭后无法再打开，除非重装系统 —— 请自行权衡

   注意：它和杀毒软件、SmartScreen 是三套独立机制 ——
   加白名单、点「仍要运行」都没用，只能关掉它本身。

■ 另外两种少见情况
   · Windows 11 S 模式（部分预装机型）：只允许商店应用，可免费退出 S 模式
   · 公司统一管控的电脑：可能只允许白名单里的程序，需要找 IT


────────────────────────────────────────────────────────
 它的"断网"是怎么做到的
────────────────────────────────────────────────────────

  断网分两层，快的先上、慢的兜底，目的就是抢在"结果上传"之前把包拦住：

   ① 快速层（毫秒级）：先试 WFP 过滤器（进程一退就自动消失，不留残留）；
      不行再加一条临时防火墙规则，把全部出站拦掉。
      开关：【⚙ 设置】→「启用快速断流」（默认开）。
   ② 硬层（原有方案，永远执行）：禁用你勾选的那张网卡 —— 3~15 秒不等，
      但最彻底，任何协议、任何程序都出不去。

  快速层只是"抢时间"：两层都装不上也照样会禁网卡，兜底效果不会比以前差。
  但它确实多了一个以前没有的故障点：那条防火墙规则是持久化的 ——
  如果程序在断网期间被强制结束（任务管理器强杀 / 断电），规则可能留在系统里（表现为"能连路由器、但上不了网"）。
  补救很简单，二选一：
     · 重新打开本程序（启动时会自动清掉残留规则并恢复网卡）；
     · 或者手动删（管理员命令行）：
         netsh advfirewall firewall delete rule name="SkyGuard-Panic-Block-Out"
  每一步都用探针自证：装不上 / 拦不住 / 恢复不了，日志里都会写明（含错误码），不会假装成功。
  关窗时如果网络还断着，程序会主动问你要不要先恢复。

  ■ 探针会不会联网
    探针就是 ping 一下你自己的路由器（默认网关），确认断流前后通不通。
    它只走局域网，不连外网（断流生效时 ping 不通）。
    想额外验证外网，可以在 guard.ini 里加一行：
        FastCutTargets=1.1.1.1:443
        （也可以直接在【⚙ 设置】→「高级选项」→「额外探测目标」里填，效果一样）
    ⚠️ 那会产生真正的外网连接，可能招来安全软件的"联网控制"提示，所以默认不这么做。

  ■ 设置窗口（分五个页签）
    · 目标程序 / 触发键 / 网卡与选项 —— 用法和以前一样；两个页签标题会显示
      「共几个、其中几个参与触发」「共几个触发键」。
    「网卡与选项」页里除了网卡，还有：焦点解堵总开关 + **接管档位（只用系统判定 / Pro / Ultra）**
      + 五个可调参数（检测间隔 / 确认次数 / 检测超时 / 交还确认次数 / 静默时间），
      外加「钩子主动探活」「使用 SeDebugPrivilege」「启用快速断流」三个开关。
    · 高级选项 —— 「关程序时网络还断着，就自动恢复」（默认开，不再每次关窗都问你）、
      「额外探测目标」（留空 = 只 ping 本机网关，不出局域网；填了会产生真正的外网连接）。
    · 维护 —— 显示版本 / 程序目录 / 数据目录，并提供
      [打开数据目录]、[导出日志]（弹出保存对话框，位置你自己选）、
      [恢复默认设置]（删掉 guard.ini，下次启动生成一份默认配置），
      以及「在主窗口显示 [状态面板] 按钮」这个开关（默认开，见下面「出问题怎么反馈」）。

  ■ 自己验一遍（推荐，尤其是换了新电脑）
    最省事：打开程序 → 点【自检】→ 选「是」跑「快速断流自检」 ——
    程序内部直接跑，跑完把报告显示在窗口里；不经过任何 .bat，也不会被 Windows 的
    "安全警告（无法验证发布者）"或安全软件挡在外面。
    也可以用命令行跑同一件事（管理员 CMD / PowerShell）：
        SkyGuardGUI.exe netcuttest
    它会真的装上快速层几秒 → 探针确认拦住 → 撤销 → 确认恢复（全程不禁用网卡），
    结果写在程序目录的 _netcuttest.txt；装不上/拦不住/恢复不了都会写清原因（含错误码）。

  ■ 万一没网了 —— 恢复脚本（程序目录里就有）
    恢复网络.bat + 恢复网络.ps1 是一对，**必须放在同一个文件夹里**（缺一个也能跑，但能力打折）。
    右键 恢复网络.bat →"以管理员身份运行"即可（双击也行，它会自己申请提权）。它会：
      · 删掉 SkyGuard 留下的防火墙规则（只删 SkyGuard-Panic-*，不动别的规则）
      · 打开被禁用的网卡 → 续租 IP → 刷新 DNS → 清 ARP 缓存
      · 最后用 ICMP 和 TCP 两条路验证默认网关，并如实告诉你通没通

    ▸ 打开网卡走**四级备选**，一级不行就换下一级（不是只有一条路）：
        T1 Enable-NetAdapter    （Win10/11 首选）
        T2 netsh interface set  （一直都有；老系统上它是主路）
        T3 Enable-PnpDevice     （设备管理器里被禁用的那种，netsh 打不开，只能靠它）
        T4 Restart-NetAdapter   （网卡是"启用"状态但没起来时用）
      每一级都会打印"做了什么 / 结果如何 / 现在什么状态"，不会出现"看起来在干活、其实没干"。
      候选网卡来自四个来源的并集（guard.ini、断网标记、Get-NetAdapter、netsh/CIM/PnP），
      任何一路读取失败都不会让名单变成空。

    ▸ 两轮策略：第一轮只动 SkyGuard **自己禁用过**的网卡（避免把你自己故意禁用的也一起打开）；
      万一第一轮没把网要回来，等 8 秒自动跑第二轮，那时广扫所有能识别的网卡兜底。
      两轮都不行会给出可照做的下一步（重启 → 设备管理器 → 退掉 VPN/加速器 → 再跑一次）。

    ▸ 换台电脑先"只看不动"验一遍（**不需要管理员、不碰任何网卡**）：
        在文件夹地址栏输入 cmd 回车，然后敲：  恢复网络.bat /dryrun
      它会列出这台机器上的适配器、判定哪些处于禁用状态、以及"本次会处理哪几张网卡"。
      如果名单里少了你要的那张，把屏幕内容发出来即可 —— 这一步就是为了在真出事之前
      确认"这个脚本认得出你的网卡"。

    日志写在 %ProgramData%\SkyGuard\RestoreNetwork.log。
    手动的话（管理员 CMD 三条）：
        netsh interface set interface name="WLAN" admin=enabled
        netsh advfirewall firewall delete rule name="SkyGuard-Panic-Block-Out"
        ipconfig /renew
    （把 WLAN 换成你自己的网卡名。）


────────────────────────────────────────────────────────
 常见问题
────────────────────────────────────────────────────────

■ 提示"需要管理员权限"
  你双击了。改成右键 → 以管理员身份运行。

■ 提示网卡不对 / 换了一台电脑
  网卡名每台机器都不一样（这台叫 WLAN，别人可能叫 Wi-Fi、以太网）。
  到【⚙ 设置】→「网卡与选项」→ 点【重新探测】，勾上带【推荐，承载流量】的那张。

■ 断网后没自动恢复
  点【恢复网络】，或点【停止保护】。
  还不行就把程序关掉重开，点【开始保护】时它会发现网卡是关着的并自动打开。

■ 按触发键没反应
  ① 看状态是不是 ● 正在保护
  ② 看底部那行「通道」是不是都有 ✓（会显示「通道 钩子✓ 轮询✓ 热键11+12」；
     有 ✗ 或整行变红就说明那条通道坏了，日志里会写清原因）
  ③ 看底部"已触发 N 次"有没有涨
  ④ 换成 F13~F24 里的一个当触发键再试（这些键基本不会被别的软件占用）
  ⑤ 如果同时显示"处置超时"或"网络操作未完成"，说明某个子进程卡住了 ——
     点【停止保护】让它收尾，或点【恢复网络】再试一次；详情看日志

■ 光遇卡白时按触发键没反应
  程序会四条路一起上（键盘钩子 / 键状态轮询 / 系统热键 / 焦点解堵）。
  焦点解堵的做法：前台窗口被判定为"无响应"，就把前台切到 SkyGuard 身上，
  让被堵住的键盘输入链解开；那个窗口一恢复，焦点自动切回游戏。
  卡白时系统会给游戏窗口套一个"幽灵窗口"（标题会变成"… (未响应)"），游戏一缓过来它就消失 ——
  这时程序按标题和配置里的目标程序把游戏窗口认回来；窗口重建期间还会先等它一下。
  要是直接还不过去（系统前台锁），它会把自己最小化让路，反正不会把焦点赖在 SkyGuard 身上。
  它一轮只做这一次 —— 不会每隔几十毫秒来回抢（那才是"焦点一直在闪"的原因）；
  你自己切到浏览器、桌面等别的窗口时，它一律不碰。
  灵敏度有三个档（⚙ 设置 → 网卡与选项 →「焦点切换档位」，默认 Pro）：
    · 仅系统检测 —— 约 5 秒后接管，
      这期间触发键可能无法使用；
    · Pro（默认）—— 约 1.6 秒后接管；
    · Ultra —— 约 0.13 秒后接管。
      优点是无响应瞬间就能接管；代价是游戏加载等场景的普通长帧也可能触发切换
      （窗口切上来再交还，看起来会闪一下）。
  同页还能细调五个参数（都保存在 guard.ini 里）：
    检测间隔 / 确认次数 / 检测超时 / 交还确认次数 / 静默时间（单位 ms）。
    界面会显示当前档位的最长等待时间，过灵敏或过保守会给出提示。
    切换档位会自动填入该档默认值，点[恢复默认值]可再套一次；改完点[确定]生效。
  短时间内反复出现无响应时，接管冷却会自动退避（1.5 秒 → 3 → 6 → …最多 30 秒），避免焦点来回切换；
  安静一分钟以上再出现，又回到 1.5 秒的快速响应。
  万一抢焦点失败（日志里写「失败(被系统前台锁挡住)」），状态栏会提示
  「抢焦点失败, 点一下本窗口」—— 点一下本窗口，按键就能用了。
  如果还是没反应，把触发键换成 F13~F24 里的一个。

■ 游戏没关掉
  用【自检】试。如果日志里出现错误码 5（拒绝访问），
  说明那个进程受系统保护，普通管理员权限动不了它。两步处理：
    ① 打开【⚙ 设置】→ 勾上「使用 SeDebugPrivilege」→ 重新开始保护再试。
       （这个开关一般情况无需开启；它的作用是让程序去申请"调试特权"，
         能多杀掉一部分受限令牌/沙箱里的进程。）
    ② 如果还是错误码 5，那就是 Windows 的系统级保护（比如浏览器沙箱、
       带内核反作弊的进程），没有任何用户态办法能杀它 ——
       这种情况靠"断网"那一刀保命就够了，不必纠结进程没关掉。
  想确认特权到底拿到没有：以管理员运行 `SkyGuardGUI.exe selftest`，
  看 `%ProgramData%\SkyGuard\_selftest.txt` 里的 `SeDebugPrivilege=` 那行。

■ 想看程序在干什么
  点【打开日志】。日志文件在数据目录（见文末「数据放哪」）：
      %ProgramData%\SkyGuard\SkyGuardGUI.log

■ 遇到问题时如何报告
  点主窗口的【状态面板】→【复制】即可复制全部内容，或点【另存为】保存为文件。
  它是一份只读信息（不改设置、不碰网卡、不结束进程），包含：
    · 环境与权限、目录与文件；
    · 键盘钩子 / 键状态轮询 / 系统热键 / 看门狗；
    · 焦点切换的当前状态；
    · 处置与网络状态；
    · 配置摘要；
    · 完整日志（含只写入文件、不显示在界面上的记录）。
  IP / MAC 已脱敏；文件路径与网卡名称会保留。
  状态面板默认开启；不想在主窗口显示该按钮，可在【⚙ 设置】→ 维护 中关闭。
  命令行也可以生成：SkyGuardGUI.exe diagtest（结果写入程序目录 _diagtest.txt）。

■ 想再看一遍首次设置向导
  在程序目录按住 Shift + 右键 →「在此处打开 PowerShell 窗口」，然后运行：
      .\SkyGuardGUI.exe wizard
  这会强制走一遍向导（演示 / 重看用），不会动你的 guard.ini。
  想真正重新配置，也可以用主界面的【⚙ 设置】。

 它做不到什么（先说清楚，别指望它兜底）
────────────────────────────────────────────────────────

  · 断网只能拦住"结果上行"，服务端已经判定完的救不回来
  · 如果数据已经写进系统缓冲区，断网也拦不住，恢复后照样会补传
  · 它不保证 100% 防坠机，是最后一道防线，不是保险
  · 真正的第一道防线是：看到不对就退
  · UAC 那个"是否允许此应用更改你的设备"的安全桌面出现时，**任何**用户态程序的
    键盘钩子 / 热键 / 键状态查询都收不到按键（这是 Windows 的设计，绕不过去）。
    应对：别把 UAC 窗口一直挂着 —— 出现就点掉，再继续游戏。
  · 游戏的"真·全屏独占"模式下，焦点解堵把前台切到本程序时，游戏可能会切一次显示模式。
    用游戏的"窗口化全屏"不会有这个问题。

 数据放哪（升级不会丢设置，靠的就是这个）
────────────────────────────────────────────────────────

  从 V1.0 起，你的设置和日志不再放程序目录，统一放在：

      %ProgramData%\SkyGuard\guard.ini          设置
      %ProgramData%\SkyGuard\SkyGuardGUI.log    日志

  在资源管理器地址栏粘贴 %ProgramData%\SkyGuard 就能打开这个文件夹。

  这么放就是为了升级：新版本直接覆盖程序目录即可，设置和日志原封不动。
  程序目录里从此只有上面列的那些程序文件，不会混进你的数据。

  老版本（V0.5 及更早）的 guard.ini / 日志在程序目录里：
  第一次运行 V1.0 时会自动复制一份到数据目录（原文件保留，不会删）。

  · 想换电脑带走设置：把 %ProgramData%\SkyGuard\guard.ini 拷过去即可
  · 想彻底重来：删掉 %ProgramData%\SkyGuard 文件夹，下次打开会重新走向导
  · 便携/临时：设个环境变量 SKYGUARD_DATA_DIR 指向任意目录即可（测试用）
  · 程序目录可以是只读的：数据全部写在 %ProgramData%，不需要程序目录可写

 怎么升级到新版本
────────────────────────────────────────────────────────

  1. 关掉正在运行的 SkyGuard（不关的话 exe 被占用，替换会提示"文件正在使用"）
  2. 两种更新方式，任选一种：

     方式一（推荐）：把新包里的所有文件复制到旧程序所在的文件夹，
       弹出"替换目标中的文件"就点替换 —— 覆盖的是文件，和文件夹叫什么无关。

     方式二：把旧的整个文件夹删掉，新包解压到任意位置（文件夹叫什么都行）。
       设置和日志在 %ProgramData%\SkyGuard，删程序文件夹碰不到它们。

  3. 重新右键 → 以管理员身份运行
  4. 想确认版本：看 version.txt，或看窗口里日志第一行"程序启动"后面的版本号

  ⚠️ 别把新包整个文件夹拖到旧文件夹旁边 —— 文件夹名字不一样，Windows 不会覆盖，
     你会得到两份程序；而且两份共用同一份设置（设置认的是 %ProgramData%，不看在哪），
     一不小心点到旧的那份，就会以为"更新了但没变化"。更新完请只留一份。

  ⚠️ 程序文件夹的名字随便起（SkyGuard / 新建文件夹 都行）—— 认版本看 version.txt
     或右键 exe → 属性 → 详细信息里的"文件版本"，不看文件夹名。

  小知识：最少只要 SkyGuardGUI.exe 这一个文件就能运行（管理员权限/DPI 那套声明是
  编译进 exe 里的），其余文件是给你看说明和以后重新编译用的。

  update.json 是给核对用的机器可读清单（文件大小 + SHA256），将来的一键更新也读它。
  想手工核对就对照 发布清单.txt 逐行比 SHA256。

  ⚠️ 自己编译出来的 exe 和包里的 exe 会「大小一样、SHA256 不一样」—— C# 编译器默认不可复现
     （PE 时间戳和程序集标识每次都变），这是正常的，不是文件被改过。
     要核对完整性，请以随包发布的 发布清单.txt / update.json 为准。
